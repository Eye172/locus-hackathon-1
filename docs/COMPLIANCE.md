# Соответствие кейсу LOCUSCASE1 и положению хакатона

Сверка по двум документам: «LOCUS Startup Hackathon 2026, кейс 01 — Визуальный профиль университета» и «Положение о
проведении LOCUS Startup Hackathon 2026, редакция 2.0». Для каждого пункта указано, где он реализован в продукте и
в коде.

## 1. Обязательный функционал (кейс, раздел 01)

| № | Требование | Реализация | Где в коде |
|---|---|---|---|
| — | Профиль не позднее чем через 30 с | первый полезный профиль за ~22–24 с для вуза, который раньше не открывали, дальше сбор идёт в фоне | `backend/app/pipeline/orchestrator.py` |
| — | Жюри повторяет сценарий с вузом вне демо | ничего не готовится заранее, любой вуз собирается вживую; индекс 14 467 вузов, плюс Wikidata, OSM и Google Карты | `backend/app/pipeline/resolve.py`, `pipeline/sources/websearch.py` |
| 1 | Поиск по названию, понятная обработка неоднозначных запросов | нечёткий поиск (опечатки, транслитерация, город в запросе), список «Вы имели в виду» с городом и страной, «не нашли» для мусора, отдельная логика для филиалов | `pipeline/resolve.py`, `frontend/src/components/SearchBox.tsx` |
| 2 | Фото кампуса, общежитий, аудиторий, библиотек и города | 8 категорий: кампус, общежитие, аудитории, библиотека, лаборатории, спорт, студенческая жизнь, город | `lib/types.ts` (`CATEGORIES`), вкладка «Фото» |
| 3 | Автоматическое разделение по категориям | CLIP zero-shot + категория от ИИ-инспектора; точность категорий 0,95 | `pipeline/categorize.py`, `pipeline/ai_inspector.py` |
| 4 | Удаление одинаковых, похожих и нерелевантных | SHA-1, pHash/dHash, косинус CLIP ≥ 0,93; проверка на сток по совпадению с другими вузами; отсев постеров, скриншотов, логотипов, баннеров | `pipeline/dedup.py`, `pipeline/crossdup.py`, `pipeline/curate.py` |
| 5 | Проверка принадлежности вузу, объекту или городу | ИИ-инспектор на каждом фото + геометка в полигоне OSM + сходство с эталоном + подпись + источник → уверенность 0–1; precision 0,94 / recall 0,94 | `pipeline/verify.py`, `pipeline/ai_inspector.py` |
| 6 | Кликабельный источник и дата | у каждого фото ссылка на пост или страницу, дата публикации или съёмки, автор и лицензия, где они есть | `components/SourceLink.tsx`, паспорт фото |
| 7 | Краткое описание кампуса по источникам | описание со сносками; справка «Что есть на кампусе», где каждое утверждение со сноской | `pipeline/describe.py`, `pipeline/campus_facts.py` |
| 8 | Фильтры «общежитие», «спорт», «лаборатории», «студенческая жизнь» | фильтры по всем категориям + «только подтверждённые», «снято за 3 года», год | `frontend/src/pages/Profile.tsx` |
| — | Путь «Название → Поиск → Проверка → Категории → Профиль» | поле поиска → перелёт с живым статусом сбора → профиль с галереей, категориями и вкладкой «Проверка» | `pages/Globe.tsx`, `pages/Profile.tsx` |
| — | Честная неопределённость | уровни «подтверждено / вероятно / отклонено» с процентом у каждого фото; фото из поиска без вердикта ИИ не показывается; пустая тема остаётся пустой с объяснением; все отклонённые — с причиной | вкладка «Проверка» |

## 3. Критерии оценивания кейса (раздел 02)

| Критерий | Вес | Чем закрыт |
|---|---|---|
| Точность и релевантность материалов | 30 % | ИИ-инспектор на каждом фото, precision 0,94 / recall 0,94; три слоя дедупликации; проверка на сток; строгие правила для поисковой выдачи; источник у каждого фото |
| Техническая реализация и архитектура | 25 % | пайплайн агентов с частичными результатами и вторым проходом; очередь проверки с приоритетом; страхующие копии запросов к Vertex AI; кэш вердиктов; откат 3D-карты и Street View; модули `sources/` и `pipeline/` |
| Удобство и понятность интерфейса | 20 % | единая дизайн-система (`docs/DESIGN.md`), 6 вкладок, фильтры, паспорт фото, понятные источники, мобильная вёрстка |
| Скорость поиска | 15 % | ~22–24 с до профиля; первые фото раньше; повторный вуз открывается сразу из прошлого сбора и тут же обновляется |
| Масштабируемость и готовность | 10 % | любой вуз мира; источник добавляется модулем в `backend/app/pipeline/sources/`; темы и языки поиска настраиваются в `/settings/search`; `POST /api/ingest` для внешних коллекторов |

Проверочный сценарий жюри (раздел 02) покрыт так:
- несколько вузов, включая вуз вне демо, — живой сбор любого вуза;
- время до результата — «Собрано за N с» под галереей и вкладка «Проверка»;
- выборка, категории, дубли, источники — вкладки «Фото» и «Проверка», паспорт фото;
- недостаток данных, ошибочное название, недоступный источник — пустые темы с объяснением, «Вы имели в виду» и «не нашли», статус каждого источника с причиной.

## 4. Разрешено и запрещено (раздел 02)

| Правило | Статус |
|---|---|
| Не выдавать стоковые и чужие фото за кампус | ✅ ИИ-флаг «сток», проверка совпадения с другими вузами, отсев фото без вердикта ИИ |
| Не скрывать ручной подбор, не имитировать автоматический поиск | ✅ ручного подбора нет: каждый профиль собирается вживую, прошлый сбор помечен и сразу обновляется |
| Не подделывать источники, скорость и достоверность | ✅ источник — настоящая ссылка на пост или страницу; время измеряется сервером; балл раскладывается по сигналам |
| Лицензии и права третьих лиц | ✅ храним превью со ссылкой на оригинал, у Commons — автор и лицензия; фото принадлежат авторам |
| Ограничение демо поддерживаемыми странами — указать честно | ✅ ограничения нет: вузы вне индекса находятся живым поиском |
| Основная логика создана за 72 часа | ✅ первый коммит 16.09.2026 21:56, история Git открыта |
| Готовые компоненты раскрыты в README | ✅ раздел «Готовые компоненты и инструменты» |
| Секреты не в репозитории | ✅ ключи только в `.env` и `backend/secrets/` (в `.gitignore`); репозиторий проверен на ключи |
