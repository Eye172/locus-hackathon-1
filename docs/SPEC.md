# CampusLense — полная функциональная спецификация

Версия 1.0 · 16 сентября 2026 · кейс 1 LOCUS Startup Hackathon 2026 (`LOCUSCASE1`)

Документ — единственный источник истины для реализации. Каждая функция описана так, чтобы её можно было отдать
ИИ-агенту в работу без дополнительных вопросов: назначение, сценарий, интерфейс, метод реализации, данные, API,
критерии приёмки, оценка времени. Ветки «MapLibre» и «Higgsfield» прописаны обе; переключение — одна настройка.

Связанные документы: `VISION.md` (обоснование и исследование), `ARCHITECTURE.md` (пайплайн и формула уверенности),
`INTEGRATION.md` (контракт с Next.js-частью), `RESEARCH.md` (замеры источников), `PLAN.md` (график).

## 1. Принципы продукта

1. **Каждое фото — проверяемое утверждение.** Источник кликабелен, дата и лицензия видны, уверенность объяснена сигналами.
2. **Ничего не подделываем.** Никаких стоковых, чужих или сгенерированных изображений в роли фото кампуса.
   Любая синтетика (катсцена Higgsfield, AI-реконструкция) подписана и отделена от фото.
3. **Скорость — свойство архитектуры.** Профиль стримится; тяжёлые украшения не блокируют результат; прогретые вузы
   открываются мгновенно; любой новый — ≤ 25 секунд.
4. **Честная неопределённость.** Пустые категории — честные пустые состояния; отклонённые фото видны с причинами.
5. **Один контракт данных.** Все части (Python, React, возможная Next.js-часть) говорят на схеме `GET /api/schema`.

Ограничения кейса, которые проверяются приёмкой: работающий сайт по ссылке без оплаты и входа; жюри вводит вуз вне
демо; время до полезного результата; категории, дубли, источники; поведение при ошибочном названии и недоступном
источнике; запрет на подделку источников, скорости и достоверности.

Тёмная тема только на лендинге (космос): фон `#050814 → #0A0A0A`, текст белый, акцент `#60A5FA`.

### 3.2. Типографика

- Заголовки: Manrope 700/800 (или Inter 800), трекинг −0.02em. H1 лендинга 56–72px, H1 профиля 28–32px.
- Текст: Inter 400/500, 15–16px, межстрочный 1.55.
- Цифры, id, тайминги: JetBrains Mono 12–13px.
- Русский, казахский, английский — шрифт покрывает кириллицу с казахскими буквами (Inter покрывает).

### 3.3. Топографический узор

Генерируется один раз скриптом `frontend/scripts/topo.mjs`: simplex-noise 2D → `d3-contour` (12 уровней) →
SVG path'ы, штрих 1px, цвет `--c-blue` c opacity 0.06 (на тёмном лендинге — белый 0.08). Файл `public/topo.svg`
~30–60 КБ, tile 1600×1600. На лендинге узор медленно смещается (`transform: translate` 60 с в цикле), на профиле
статичен под шапкой и в пустых состояниях. Правило: узор никогда не спорит с фотографиями — под сеткой фото фон чистый.

### 3.4. Компоненты и радиусы

Карточки `rounded-2xl` (16px), тени 0 1px 2px rgba(10,10,10,.05); чипы `rounded-full` 12px текст; кнопки 12px радиус,
высота 40px; поля ввода 44px; модальные окна 20px радиус, затемнение 60% + blur 6px. Иконки — lucide, 16/20px.

### 3.5. Движение

| Событие | Длительность | Кривая |
|---|---|---|
| Вращение глобуса в покое | 120 с/оборот | линейно |
| Перелёт к вузу | 2.4–2.8 с | MapLibre `flyTo` (curve 1.6) |
| Пролёт облаков | 0.9 с в середине перелёта | ease-in-out, opacity 0→0.85→0 |
| Возведение зданий | 1.2 с | ease-out-cubic |
| Появление карточек стрима | 250 мс, каскад 40 мс | ease-out |
| Модальные окна | 200 мс | ease-out |
| Диаграммы при входе во вьюпорт | 600 мс | ease-out |

`prefers-reduced-motion`: перелёт заменяется на `jumpTo` + fade, здания появляются без анимации.

### 3.6. Диаграммы (единый стиль)

Тонкие оси, без фонов, подписи 12px `--c-ink-2`, акцент `--c-blue`, вторичные серии `#93C5FD`/`#BFDBFE`. Каждая
диаграмма имеет: заголовок, подпись источника с ссылкой, год данных, состояние «нет данных».

## 5. Функции

Формат каждой функции: **Цель · Сценарий · Интерфейс · Реализация · Данные и API · Приёмка · Оценка (часы)**.

### F1. Планета в космосе + поиск (лендинг)

**Цель.** Первое впечатление и вход в поиск: вуз — точка на планете.

**Сценарий.** Открыл сайт → глобус медленно вращается на фоне звёзд, на нём светятся точки вузов (кластеры на дальнем
зуме) → поле поиска по центру снизу → ввод «CUHK Shenzhen» → список кандидатов с флагом, городом, страной → клик.

**Интерфейс.** Полноэкранный canvas MapLibre (globe), градиент космоса, слой звёзд (canvas 2D, 400 точек, мерцание),
лёгкая атмосфера. Поверх: заголовок (2 строки), поле поиска 560px с иконкой и подсказкой «КазНУ, Nazarbayev
University, CUHK…», под ним чипы быстрых стран: 🇰🇿 Казахстан, 🇰🇬 Кыргызстан, 🇺🇿 Узбекистан, 🌍 Мир. Внизу слева
статус: «14 467 вузов · 10 045 с координатами · источники: Wikidata, OSM, Commons».

**Реализация (MapLibre).** `new maplibregl.Map({style: 'https://tiles.openfreemap.org/styles/liberty', projection:{type:'globe'}, zoom: 1.6, center:[66, 48]})`;
фон стиля перекрашен в тёмный (слои `background`, `water` → тёмно-синие, `land` → `#0D1730`); `map.setSky/setFog` для
атмосферы; авто-вращение через `requestAnimationFrame` (`map.easeTo({bearing})` или прибавление к `center.lng`),
останавливается при взаимодействии и во время поиска. Точки: `public/universities.geojson` (генерируется из индекса,
~10 045 point features, 2,4 МБ / ~600 КБ gzip) → `cluster: true` источник, круги с `--c-blue` и свечением (два слоя circle).

**Реализация (Higgsfield-ветка).** Фон лендинга — зацикленный WebM «Земля из космоса» (8–10 с), сгенерированный в
Higgsfield; глобус MapLibre всё равно нужен для точек и перелётов, поэтому ветка меняет только фон, см. §10.

**Данные и API.** `GET /universities.geojson` (статический файл фронтенда), `GET /api/search?q=`.

**Приёмка.** Лендинг интерактивен ≤ 2 с на ноутбуке; глобус 60 fps; поиск с опечатками работает («Univer Almatyy»,
«Сатпаев»); клик по точке открывает мини-карточку (F4).

**Оценка.** 5 ч.

### F2. Перелёт к вузу через облака

**Цель.** Кинематографичный переход от планеты к кампусу, под который уже собирается профиль.

**Сценарий.** Клик по кандидату → глобус доворачивается к точке → камера поднимается, проходит через слой облаков,
опускается к кампусу с наклоном 60° → здания «возводятся» (F4) → внизу выезжает панель профиля с первыми фото.

**Реализация (MapLibre).** `map.flyTo({center, zoom: 16.3, pitch: 60, bearing: -17, speed: 0.85, curve: 1.7, essential: true})`.
Облака: div-слой `#clouds` с двумя PNG-спрайтами облаков (полупрозрачные, 2048px), включается при `zoom ∈ [3.5, 9]`
в событии `move`, opacity по колоколу, лёгкий сдвиг по X. Параллельно `navigate('/u/:qid')` с сохранением карты
(глобус живёт в layout вне роутов: одна инстанция MapLibre на всё приложение, страница профиля — панель поверх).
Стрим профиля стартует в момент клика, не после перелёта.

**Реализация (Higgsfield).** Если для `qid` есть файл `cutscenes/{qid}.webm`: показать полноэкранное видео (2.5–4 с)
с crossfade в конечное положение камеры MapLibre (`jumpTo` в тот же ракурс); иначе — flyTo. Подпись в углу
«анимация перехода». См. §10.

**Приёмка.** Перелёт 2.4–2.8 с без рывков; первые фото в панели видны к концу перелёта для прогретых вузов и ≤ 4 с для
новых; кнопка «пропустить» есть.

**Оценка.** 3 ч (MapLibre) + 2 ч (интеграция видео).

### F3. Карта вузов по странам

**Цель.** Исследование «а что ещё есть»: вузы страны на карте, переходы между странами.

**Сценарий.** Клик по чипу страны или `/countries/KZ` → камера облетает к стране (flyTo zoom 4.5–5.5, pitch 30) →
точки вузов с подписями при зуме ≥ 6 → наведение — мини-карточка → клик — перелёт (F2). Стрелки «соседние страны».

**Реализация.** Границы и центры стран — `public/countries.json` (ISO, bbox, центр, соседи) для 45 стран индекса.
Фильтр слоя точек по `country`. Список вузов страны в боковой панели с сортировкой по числу студентов и покрытию
профиля (из `/api/recent`/кэша).

**API.** Нет новых; `GET /api/universities/stats` (число вузов на страну) — опционально, можно посчитать на клиенте.

**Приёмка.** Для Казахстана — 93 точки, подписи не перекрываются (`text-allow-overlap:false`), переход между
странами ≤ 2 с.

**Оценка.** 2.5 ч.

### F4. 3D-модель кампуса, окрестности, город, маршруты, иконки

**Цель.** «Вижу кампус объёмно, где он относительно города и что рядом».

**Сценарий.** После перелёта здания поднимаются из земли; полигон кампуса подсвечен; здания внутри окрашены по типу;
линия до центра города с временем в пути; иконки: метро/остановки, кафе, парки, спортзалы, супермаркеты, аптеки,
ТЦ. Наведение на здание — подпись (название корпуса, тип, из OSM). Кнопка «Обойти» ведёт в F6.

**Интерфейс.** Вкладка «3D-карта» профиля (и та же карта живёт под панелью). Легенда типов зданий. Панель «Город»:
расстояние и время до центра (пешком/машина), остановки в 800 м, список POI с числами и иконками, «до аэропорта».

**Реализация (MapLibre).**
- Слой `fill-extrusion` из OpenFreeMap (`source-layer: building`, `render_height`/`render_min_height`); высота по
  умолчанию 12 м, если нет; анимация: `map.setPaintProperty('buildings','fill-extrusion-height',['*',['coalesce',['get','render_height'],12], t])`,
  `t` 0→1 за 1.2 с.
- Здания кампуса: из профиля (`campus.buildings` с координатами и `kind`) — раскраска через `feature-state` для
  зданий OpenFreeMap, попавших внутрь полигона (клиентский point-in-polygon по центру тайла-фичи через
  `map.queryRenderedFeatures`) либо отдельный слой из Overpass-геометрии (`/api/context` отдаёт полигоны зданий кампуса).
- Полигон: `fill` 8% + `line` 2px `--c-blue`; в режиме радиуса — пунктирная окружность.
- Маршрут: `GET /api/context/{qid}` → `route_center.geometry` (GeoJSON LineString) слоем `line`, пунктир.
- POI: `context.poi[]` → слой символов с иконками lucide (спрайт из SVG), кластеризация при зуме < 14.
- Освещение и сезон (P1): `map.setLight({anchor:'map', position:[1.5, azimuth, polar]})` от ползунка «месяц/час»;
  зимой стиль воды/земли холоднее.

**Реализация (Higgsfield).** Не заменяет: 3D-здания остаются MapLibre. Катсцена только для перелёта.

**Данные и API.** `GET /api/context/{qid}` (§6.6): центр города, маршрут, остановки, POI, аэропорт/вокзал; кэш 7 дней.

**Приёмка.** Здания видны для любого вуза, где OSM имеет footprints (проверить КазНУ, НУ, КБТУ, ETH, CUHK Shenzhen);
анимация 60 fps на ноутбуке; POI ≥ 5 категорий для городских кампусов; при отсутствии данных — «нет данных OSM».

**Оценка.** 6 ч (здания, полигон, маршрут, POI) + 2 ч (свет/сезон).

### F5. Higgsfield-катсцены (ветка)

Полностью описано в §10. Резюме: пререндер видео «космос → облака → город → кампус» для 10–15 прогретых вузов,
воспроизведение как переход с crossfade в MapLibre, подпись «анимация», fallback flyTo. Оценка: 4 ч интеграции +
время генерации (≈ 10–15 мин на вуз).

### F6. Обход кампуса: панорамы, параллакс, 360

**Цель.** «Пройтись» по кампусу и окрестностям на реальных снимках.

**Сценарий.** Клик по зданию/точке на 3D-карте → карточка над ним (название, тип, 2 лучших фото, «Смотреть с улицы»)
→ открывается панель обхода: панорама Street View/Mapillary у ближайшей точки, стрелки перемещения, кнопки «след.
корпус». Вкладка «Обход» также содержит ленту «3D-фото»: проверенные фото с параллаксом при движении мыши/гироскопа.

**Интерфейс.** Панель 40% ширины справа на десктопе (полноэкранная на мобильном): вверху переключатель
Street View / Mapillary / 3D-фото; внизу мини-карта с точкой обзора и направлением; подпись источника и даты снимка.

**Реализация.**
- `maplibre-gl-streetview` контрол: `new StreetViewControl({googleApiKey, mapillaryAccessToken, defaultProvider: googleApiKey ? 'google' : 'mapillary'})`;
  при клике по карте плагин сам находит ближайшее покрытие. Без ключей панель показывает только «3D-фото».
- 3D-фото: `GET /api/depth/{photo_id}.png` (сервер считает Depth Anything V2 Small при первом запросе, кэш на диске,
  ~0.3–0.6 с на CPU; для прогретых вузов считается заранее для топ-12 фото). Клиент: WebGL-плоскость 128×96
  сегментов, вершины смещаются по глубине (`z = depth * 0.08`), камера слегка двигается за курсором/гироскопом;
  fallback без WebGL — CSS-параллакс двух слоёв. Подпись «параллакс по карте глубины, фото не изменено».
- «Обход» как маршрут: последовательность точек — вход в кампус (ближайшая точка покрытия к полигону), затем здания
  по типу (корпус → библиотека → общежитие → спорт), кнопки «далее/назад», плавный `flyTo` мини-карты.
- AI-реконструкция недостающих видов — **не входит в основной продукт** (см. VISION §3.3). Опциональный
  эксперимент P2: отдельная вкладка «AI-сцена (не фото)» для 2 прогретых вузов через World Labs/HunyuanWorld, с
  водяным знаком; включается флагом `AI_SCENES=1`.

**Данные и API.** `GET /api/depth/{photo_id}.png`; профиль (`photos`, `campus.buildings`); ключи Google/Mapillary
на клиенте (публичные, ограничить по referrer).

**Приёмка.** Для КазНУ/НУ открывается панорама у входа (Street View покрывает Алматы/Астану); 3D-фото плавное 60 fps;
без ключей интерфейс честно показывает, что панорамы отключены.

**Оценка.** 3 ч (панорамы) + 3 ч (глубина, сервер) + 5 ч (WebGL-параллакс и «обход»).

### F10. Климат и погода

**Цель.** Понять, как живётся в этом городе по сезонам, а не «+20/−10».

**Интерфейс.** Вкладка «Климат»:
1. Кольцевой график года: 12 секторов, цвет — средняя температура (шкала −30…+35 → синий→белый→красный), радиус — осадки.
   В центре: средняя годовая, «дней с осадками», «часов солнца в год».
2. Четыре сезона (карточки): средняя/ощущаемая температура, мин/макс, влажность, дней с осадками, снежных дней,
   солнце (ч/день), ветер (м/с). Фон — градиент сезона.
3. Стек комфорта: доля дней «комфортно / прохладно / морозно / жарко / дождливо» за год с подписью, как считали.
4. Роза ветров по месяцам (SVG, 16 румбов).
5. Живой слой: Windy embed (`embed.windy.com/embed2.html?lat&lon&zoom=8&overlay=wind`) или тайлы OpenWeatherMap
   (температура/облака/ветер) поверх мини-карты региона; переключатель ветер/облака/температура.
6. «Как ощущается» — 3–4 предложения (LLM по числам; без ключа — шаблон), с подписью «по данным Open-Meteo, ERA5, 2025».
7. Сейчас: текущая погода и прогноз на 5 дней (Open-Meteo forecast) — небольшой ряд иконок.

**Реализация.** `GET /api/climate/{qid}` собирает архив за последний полный год (daily: `temperature_2m_mean/max/min`,
`apparent_temperature_mean`, `relative_humidity_2m_mean`, `precipitation_sum`, `snowfall_sum`, `sunshine_duration`,
`cloud_cover_mean`, `wind_speed_10m_max`, `wind_direction_10m_dominant`) + forecast (current, daily 5 дней) → агрегаты
по месяцам/сезонам, индекс комфорта, роза ветров, текст. Кэш 30 дней в `climate_cache`. Диаграммы — Recharts
(RadialBar/PieChart для кольца, BarChart стек) + SVG-роза.

**Приёмка.** Для Алматы кольцо показывает холодную зиму и жаркое лето; все числа со ссылкой; при отказе Open-Meteo —
состояние «климат недоступен, повторить».

**Оценка.** 3 ч backend + 6 ч frontend.

## 6. API

Базовый URL: `/api`. Все ответы JSON (UTF-8). Ошибки — `{error: string, detail?: string}` с кодом 4xx/5xx.
CORS открыт. Схемы: `GET /api/schema`.

### 6.1. Поиск и справочники

| Метод | Путь | Запрос | Ответ |
|---|---|---|---|
| GET | `/api/search` | `q` (1–120 символов) | `{query, candidates: Candidate[]}` — до 10, отсортировано по score |
| GET | `/api/mini/{qid}` | — | `{qid, name, names, city, country, founded, students, logo_url, lat, lon, profile: {coverage, photos: PhotoRef[3], generated_at} \| null}` |
| GET | `/api/universities/stats` | — | `{by_country: {ISO: count}}` |
| GET | `/api/recent` | — | `{recent: RecentItem[]}` |
| GET | `/api/sources` | — | статус источников и ключей |
| GET | `/api/health` | — | `{ok, clip_ready, index, budget_s}` |
| GET | `/api/schema` | — | JSON Schema моделей |

Статический: `frontend/public/universities.geojson` — FeatureCollection точек `{qid, name, name_en, city, country, students}`; генерируется `backend/scripts/export_geojson.py`.

### 6.2. Профиль

| Метод | Путь | Запрос | Ответ |
|---|---|---|---|
| GET | `/api/profile/{qid}` | — | `Profile` из кэша или 404 |
| GET | `/api/profile/{qid}/stream` | `refresh=0/1` | SSE: `stage`, `university`, `campus`, `source`, `photos`, `profile`, `error` |
| POST | `/api/profile/{qid}/refresh` | — | `{ok}` (удаляет кэш) |
| POST | `/api/flag` | `{qid, photo_id, reason}` | `{ok, flags}` |
| POST | `/api/ingest` | `ExternalCandidates` | `{ok, stored, next}` |
| GET | `/api/thumb/{photo_id}.jpg` | — | JPEG превью ≤ 640px |
| GET | `/api/depth/{photo_id}.png` | — | PNG 16-бит карта глубины (ленивая генерация, кэш) |

События SSE (формат `event: <type>`, `data: JSON`):
- `stage {stage: Stage, elapsed_ms}`
- `university {university: University, campus: Campus, elapsed_ms}`
- `campus {campus, university, elapsed_ms}` — когда полигон найден
- `source {name, status, count, ms, detail, label, elapsed_ms}`
- `photos {source, preliminary: true, photos: Photo[], rejected: n, elapsed_ms}`
- `profile {profile: Profile, cached?: bool, elapsed_ms}`
- `error {message, log: string[], elapsed_ms}`

## 8. Пайплайн достоверности

| Агент | Вход | Выход | Метод | Время |
|---|---|---|---|---|
| Scout | QID, факты, полигон | кандидаты (URL, источник, метаданные) | 9 источников параллельно, таймаут 6 с, ≤ 40 на источник | 3–8 с |
| Fetcher | кандидаты | изображения ≥ 300px, EXIF, SHA-1, pHash, dHash | 10 параллельных загрузок, 5 с на файл, ресайз 640 | 2–8 с |
| Inspector | изображение + контекст | сигналы и уверенность | CLIP-семантика, полигон OSM, алиасы, кросс-источник, дата, флаги (веса — ARCHITECTURE §3) | 0.05 с/фото |
| Curator | все фото | группы копий, кластеры похожих, мусор | SHA-1 → pHash ≤ 8 → косинус ≥ 0.93; zero-shot мусор (логотип, карта, скриншот, документ, постер, портрет, схема, сертификат) | 0.5 с |
| Judge | фото 0.30–0.65 (≤ 10) | `{is_campus_photo, category, reason}` | Gemini 2.5 Flash vision, JSON-схема, кэш по SHA-1; +0.15/−0.25 к уверенности | 1–3 с параллельно |
| Writer | факты + фото > 0.5 + климат + город | описание с цитатами | Gemini/Claude/шаблон | 2–4 с параллельно |

Пороги: `verified ≥ 0.65`, `likely ≥ 0.30` (было 0.40 — снижаем, чтобы судья мог поднять), `< 0.30` — отклонено.
Категории: 8, приоры от тегов зданий OSM и ключевых слов ru/kk/en. Eval: `scripts/eval.py` по `labels.json` → precision/recall в README и в режиме жюри.

## 9. Взаимодействие частей и бюджет времени

### 9.1. Последовательность «клик по вузу»

```
t=0.0  клик по кандидату
       ├─ Frontend: flyTo (2.6 с) + облака; route → /u/:qid (панель поверх карты)
       ├─ Frontend: GET /api/mini/{qid} → шапка панели за 150 мс
       ├─ Frontend: EventSource /api/profile/{qid}/stream
       │     кэш есть → profile за ~100 мс; нет → facts 1 с → photos с 3–4 с → profile ≤ 25 с
       ├─ Frontend (после прилёта, t≈2.6): 3D-здания OpenFreeMap (уже в тайлах) + анимация 1.2 с
       ├─ Frontend: GET /api/context/{qid} (кэш 7 дн; первый раз 3–6 с) → маршрут, POI
       └─ Frontend: GET /api/climate/{qid} (кэш 30 дн; первый раз 1.5–3 с) → вкладка «Климат»
t=2.6  прилёт, здания поднимаются, в панели уже видны первые фото (прогретые — все)
t≤25   финальный профиль, описание, покрытие
```

### 9.2. Бюджеты

| Метрика | Цель |
|---|---|
| Лендинг интерактивен | ≤ 2 с (глобус первый кадр ≤ 1 с, точки ≤ 1.5 с) |
| Поиск (индекс) | ≤ 80 мс; с Wikidata ≤ 2 с |
| Мини-карточка | ≤ 150 мс (кэш) |
| Первые фото нового вуза | ≤ 4 с |
| Полный профиль нового вуза | ≤ 25 с (жёсткий бюджет, частичный результат при превышении) |
| Прогретый профиль | ≤ 300 мс |
| Контекст, климат (кэш) | ≤ 300 мс; первый раз ≤ 6 с, не блокируют |
| Карта глубины | ≤ 0.6 с/фото, для прогретых — заранее |
| Сравнение ИИ | ≤ 6 с; чат — первый токен ≤ 1.5 с |

### 9.3. Где что исполняется

- **Клиент:** глобус, перелёт, 3D-здания (тайлы OpenFreeMap напрямую), панорамы (Street View/Mapillary напрямую),
  Windy-оверлей, параллакс, localStorage.
- **Python:** всё, что требует проверки или агрегации: пайплайн, климат, контекст, стоимость жизни, судья, описание,
  сравнение, чат, глубина, OG.
- **Кэши:** SQLite (профили, климат, контекст, судья, сравнения), диск (превью, глубина), браузер (localStorage,
  HTTP-кэш превью `max-age=86400`).

### 9.4. Одна инстанция карты

MapLibre создаётся один раз в корневом layout и переиспользуется на всех экранах (лендинг, профиль, обход, страны).
Роуты рисуют панели поверх. Это убирает повторную загрузку стиля и делает переходы бесшовными.

## 10. Ветка Higgsfield: катсцены перехода

**Когда включать.** Если после теста MapLibre-перелёта команда решит, что нужен «кинематограф». Ветка не отменяет
MapLibre: 3D-здания, точки, страны остаются; видео заменяет только 2.6 с перелёта для прогретых вузов.

**Производство.**
1. Список 10–15 вузов из `prewarm_list.json` (все демо-кандидаты + 5 мировых).
2. Для каждого: референсы — 2–3 подтверждённых фото кампуса (уверенность ≥ 0.65) + кадр MapLibre конечного ракурса
   (скриншот 1920×1080 с pitch 60, bearing −17, zoom 16.3) — чтобы конец видео совпал с картой.
3. Higgsfield: image-to-video с движением камеры «orbit/push-in», промпт: «cinematic descent from orbit through thin
   clouds to a university campus at golden hour, ends on this exact view», длительность 4–5 с, 1080p, 24 fps.
4. Постобработка (ffmpeg): обрезать до 3.5–4 с, добавить 0.4 с затемнения в конце, экспорт WebM (VP9, ~3–5 МБ) и
   MP4 (H.264) для Safari; `cutscenes/{qid}.webm|mp4`; манифест `cutscenes/index.json` `{qid: {webm, mp4, end_camera}}`.
5. Хранение: Vercel `public/` (до ~100 МБ суммарно нормально) или Cloudflare R2/S3 (бесплатные лимиты).

**Интеграция.** `flyOrPlay(qid)`: если `cutscenes/index.json` содержит `qid` и видео предзагружено (`<link rel=preload>`
при наведении на кандидата) — полноэкранный `<video>` с `playsInline muted`, поверх — подпись «анимация перехода», кнопка
«пропустить»; по `ended` → `map.jumpTo(end_camera)` + crossfade 300 мс + анимация зданий. Если видео не готово за
250 мс — обычный flyTo. Настройка `VITE_CUTSCENES=1`.

**Честность.** Видео — художественная анимация, не является фотографией; в паспортах и альбомах не участвует;
в режиме жюри отмечено «синтетика: только переходы».

**Стоимость и время.** Подписка Higgsfield (тариф с кредитами на 15+ видео), ~10–15 мин на вуз с итерациями;
интеграция 4 ч.

### 12.2. Приёмочный сценарий (как будет проверять жюри)

1. Открыть сайт в приватном окне без входа → лендинг ≤ 2 с, глобус вращается.
2. Ввести «Univer Almatyy» → есть кандидаты алматинских вузов; ввести «qwerty» → честное «не нашли».
3. Выбрать вуз, которого нет в демо (например, «Университет Мальты») → перелёт, первые фото ≤ 4 с, профиль ≤ 25 с
   или частичный с пометкой; засечь время в полосе пайплайна.
4. Открыть 5 фото → у каждого источник открывается и содержит это фото; сигналы объясняют уверенность.
5. Вкладка «Отклонено» → причины понятны; «Брошюра vs реальность» → обе стороны подписаны.
6. Категории и фильтры кейса присутствуют; пустая категория показывает, где искали.
7. 3D-карта: полигон, здания, маршрут до центра, POI; «Обход» открывает панораму или честно сообщает об отсутствии.
8. «Климат»: кольцо года, сезоны, источник и год; «Город»: транспорт, бюджет с источником.
9. Сохранить два вуза → «Сравнить» → плюсы/минусы по фактам, чат отвечает числами.
10. Режим жюри: тайминги, источники, лог, ссылка на схему, precision.
11. Отключить сеть на источнике (симуляция: неверный домен сайта) → профиль всё равно собирается, источник помечен.
12. Мобильный экран 390px: всё читаемо, глобус и панель не ломаются.
