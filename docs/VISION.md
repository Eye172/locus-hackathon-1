# CampusLens — видение продукта, разбор идей, стек и план на 1 место

Дата: 16 сентября 2026, ~15:00. До дедлайна ≈ 69 часов. Документ отвечает на вопросы из чата: что из идей
реализуемо, чем, за сколько, как всё связать, кто что делает, нужна ли БД, как уложиться в 30 секунд.

---

## 0. Резюме решений

1. **Планета → перелёт → 3D-кампус делаем на MapLibre GL JS + OpenFreeMap.** Бесплатно, без ключей, работает для
   любого вуза мира: глобус с атмосферой, `flyTo` с пролётом через «облака», 3D-здания из OpenStreetMap, которые
   анимированно «возводятся». Higgsfield для этого не нужен: готовые видеокатсцены нельзя сделать за 30 секунд для
   вуза, которого жюри введёт впервые. Higgsfield — только для 15-секундного интро в демо-видео.
2. **Обход кампуса делаем на реальных данных:** Google Street View (Embed API бесплатен, Казахстан покрыт с 2024 года)
   + MapillaryJS (готовый плагин `maplibre-gl-streetview` умеет оба) + наша «3D-фотография» с параллаксом по карте
   глубины (Depth Anything V2 в браузере). Генерировать недостающие части кампуса ИИ **не будем**: кейс прямо
   штрафует за чужие/поддельные изображения, а критерий точности весит 30%.
3. **БД с ссылками — да.** Уже есть офлайн-индекс 14 467 вузов из Wikidata и SQLite-кэш профилей. Добавляем
   прогрев ~150 вузов (все KZ + Центральная Азия + топ мира), чтобы демо и сравнение открывались мгновенно, а любой
   новый вуз собирался вживую за ≤ 25 секунд. Храним ссылки и метаданные, не сами фото.
4. **ИИ-агенты — это наш пайплайн:** поиск → проверка (CLIP + полигон + сигналы) → дубли (pHash/SHA-1/косинус) →
   уверенность 0–1 → порог. Добавляем второе мнение vision-модели (Gemini, бесплатный тариф без карты) для спорных
   фото и ИИ-описание по фото с уверенностью > 0.5 плюс открытые данные.
5. **Дизайн:** белый + синий + чёрный, минимализм, топографический узор на фоне, данные показываем диаграммами
   (кольцевой график года, сезонные карточки, роза ветров, покрытие по категориям).
6. **Сохранение карточек, сравнение и ИИ-чат** — да, на Gemini free tier, с жёстким правилом «только факты из профилей».
7. **Скорость:** три уровня — прогретые профили (мгновенно), живая сборка (≤ 25 с, первые фото через 3–4 с),
   тяжёлые украшения (3D, маршруты, погода) грузятся на клиенте параллельно и не блокируют результат.

## 1. Что требует кейс и что запрещено (проверка идей)

Критерии предварительной оценки: точность и релевантность **30%**, техническая реализация **25%**, UX **20%**,
скорость **15%**, масштабируемость **10%**. Жюри вводит вуз, которого нет в демо, замеряет время, кликает по
источникам, ломает ввод.

Запрещено: стоковые или чужие фото как фото кампуса; скрытый ручной подбор; подделка источников, скорости,
показателя достоверности. «Количество фотографий не является преимуществом».

Вывод для идей:

| Идея | Совместимость с кейсом | Что менять |
|---|---|---|
| Планета и перелёт | Полностью совместимо: это UX + масштабируемость (любой вуз мира) | Не блокировать результат анимацией: профиль стримится под анимацией, к концу перелёта первые фото уже есть |
| 3D-модель кампуса | Совместимо, если модель из реальных данных (OSM-здания, Google 3D Tiles) | Никаких «додуманных» зданий; подпись «здания из OpenStreetMap» |
| Обход с параллаксом/360 | Совместимо на реальных панорамах (Street View, Mapillary) и на наших проверенных фото | ИИ-генерация недостающих видов — **нет**. Максимум: отдельный, явно подписанный режим «AI-реконструкция» как эксперимент, не в основном пути |
| Мини-профили и БД | Требуется кейсом (профиль, категории, источники) | Прогрев ≠ хардкод: те же алгоритмы, только заранее; в интерфейсе «собрано 16.09, пересобрать» |
| Климат, транспорт, стоимость жизни | Прямо перечислены в «дополнительных функциях» | Стоимость жизни — только с источником и датой |
| Сохранение, сравнение | Сравнение двух вузов — доп. функция кейса | ИИ-чат должен цитировать профили, не выдумывать |

## 2. Идея 1. Планета в космосе → перелёт → 3D-кампус

### 2.1. Как это сделать бесплатно и быстро

**Ядро: MapLibre GL JS (v5/v6) + OpenFreeMap.**
- Глобус: `map.setProjection({type: 'globe'})`, атмосфера и «космос» через `sky`/`fog`, фон — звёздное небо CSS/canvas.
- Точки вузов: наш индекс (10 045 вузов с координатами) → GeoJSON-слой с кластерами; наведение → карточка.
- Перелёт: `map.flyTo({center, zoom: 16.5, pitch: 60, bearing: -20, curve: 1.6, speed: 0.9})` — камера уходит вверх,
  проходит через слой облаков и опускается к кампусу. «Облака» — полупрозрачный canvas-слой с шумом, который
  показывается на средних зумах (z 4–9) и рассеивается; дёшево и выглядит как пролёт.
- 3D-здания: слой `fill-extrusion` из OpenFreeMap (здания OSM с высотами). Эффект «возводится»: высота = `['*', ['get','render_height'], t]`,
  где `t` анимируется 0→1 за 1.2 с после прилёта. Полигон кампуса подсвечивается, здания внутри окрашиваются по типу
  (общежитие/библиотека/спорт/корпус — у нас уже есть теги из Overpass).
- Город рядом: линия до центра города, время в пути (OSRM), иконки POI вокруг кампуса (Overpass: кафе, парки, метро,
  ТЦ, больницы, спортзалы — счётчики и пины).
- Готовые примеры MapLibre: «Display a globe with a fill extrusion layer», «Display buildings in 3D», `flyTo`.

**Апгрейд, если будет ключ Google с биллингом:** Photorealistic 3D Maps (`gmp-map-3d`, `flyCameraTo`, `flyCameraAround`) —
фотореалистичные города. Минусы: платный SKU Immersive Maps, покрытие Казахстана фотореалистикой не подтверждено,
нужен биллинг. Держим как опцию для стран, где покрытие есть; MapLibre остаётся базой.

**Landing-вариант «космос»:** `three-globe`/`globe.gl` (three.js) для эффектной заставки с дугами и точками; по клику
плавно заменяем на MapLibre. Это +3–4 часа; сначала делаем MapLibre-глобус, three-globe — если останется время.

**Higgsfield AI.** Это генератор видео с кинематографичными движениями камеры. Полезен для: интро демо-видео,
фоновой заставки на лендинге (один зацикленный ролик «Земля из космоса»). Для перелётов к произвольному вузу
не подходит: генерация занимает минуты и не привязана к реальной геометрии.

### 2.2. Оценка

| Часть | Часы | Кто |
|---|---|---|
| Глобус + точки + перелёт + облака | 5 | Frontend |
| 3D-здания + анимация «возведения» + раскраска по тегам | 4 | Frontend |
| Маршрут до центра (OSRM) + POI-иконки (Overpass) | 3 | Backend + Frontend |
| Режим «карта вузов по странам» с кластерами | 2 | Frontend |

## 3. Идея 2. Обход кампуса, параллакс, 360

### 3.1. Реальные панорамы

- **Google Street View через Maps Embed API** — бесплатно и без лимитов (нужен ключ Google Maps; сам Embed не тарифицируется).
  Казахстан покрыт: Астана, Алматы, Шымкент, Актобе, Семей и 42 000 км дорог. У большинства кампусов будет вид с улицы.
- **MapillaryJS** — бесплатный клиентский токен, готовый WebGL-вьюер с навигацией по кадрам и 360-панорамами.
- **Плагин `maplibre-gl-streetview`** — контрол для MapLibre, умеет оба провайдера, сам ищет ближайшее покрытие.
  Клик по карте кампуса → панель с панорамой. Это ровно «пройтись как в Google Maps», готовое.

### 3.2. «3D-фотография» из наших проверенных фото (изюминка)

Для каждого фото с уверенностью ≥ 0.65 считаем карту глубины (Depth Anything V2 Small: ONNX, 25M параметров,
работает в браузере через transformers.js на WebGPU/WASM, либо на сервере на CPU ~0.3 с/фото). В паспорте фото и в
«обходе» рисуем фото на сетке со смещением по глубине: при движении мыши/гироскопа ближние объекты сдвигаются
сильнее — эффект «3D-фото», как у Facebook. Честно: это те же реальные пиксели, просто с объёмом. Подпись
«параллакс по карте глубины, фото не изменено».

Обход = последовательность: панорама у входа (Street View/Mapillary) → 3D-фото корпусов по категориям → карта.
Переходы — плавные, как слайды с Ken Burns.

### 3.3. Почему не генерируем недостающие виды ИИ

World Labs Marble (World API, январь 2026) и HunyuanWorld/HY-World 2.0 (open source, апрель 2026) умеют строить
3D-мир из одного фото. Но: (а) результат — синтетика, а кейс штрафует чужие/поддельные виды; (б) генерация занимает
минуты и требует GPU/платного API — не укладывается в 30 секунд для нового вуза; (в) жюри проверяет «принадлежность
фотографии университету» — у сгенерированного вида её нет. Если очень хочется «вау»: P2-эксперимент только для 2–3
прогретых вузов, отдельная вкладка «AI-реконструкция (не фото)» с водяным знаком. В демо-видео — не показывать как
основную функцию.

### 3.4. Оценка

| Часть | Часы | Кто |
|---|---|---|
| Street View/Mapillary панель на карте кампуса | 3 | Frontend |
| Карты глубины (сервер, батч в пайплайне, кэш) | 3 | Backend |
| WebGL-параллакс в паспорте фото + «обход» | 5 | Frontend |

## 4. Идея 3. Мини-профили и база данных

**Что уже есть:** `data/universities.json` (14 467 вузов, labels ru/en/kk, алиасы, координаты, сайт, категория Commons)
и SQLite-кэш профилей (JSON целиком, флаги пользователей, внешние кандидаты).

**Решение по БД:** остаёмся на SQLite для хакатона (один файл, ноль настройки), но храним **ссылки и метаданные**,
а не изображения: у каждого фото `url` оригинала, `page_url` источника, лицензия, автор, дата, хэши. Превью кэшируются
на диске как ускорение, оригиналы всегда доступны по ссылке. Если Next.js-часть будет деплоиться отдельно и ей нужен
общий доступ — переезд на Postgres (Neon/Supabase free) занимает час: схема — одна таблица `profiles(qid, json)`.

**Прогрев (pre-warm):** скрипт `scripts/prewarm.py` собирает профили для списка: все вузы Казахстана из индекса (93),
топ-5 каждой страны Центральной Азии, 40 мировых (MIT, ETH, Оксфорд, CUHK, Токио, KAIST, NUS…). Это ~150 профилей ×
~20 с = 50 минут фоновой работы. В интерфейсе честно: «профиль собран 17.09 12:40 · пересобрать».

**Мини-профиль (карточка при наведении на глобусе):** название, город, логотип, число студентов, год, покрытие,
3 лучших фото — всё из кэша, мгновенно.

## 5. Климат и погода — красиво и честно

**Источник: Open-Meteo** (бесплатно, без ключа, 10 000 запросов/день): архив ERA5 с 1940 года, дневные переменные —
температура (мин/макс/средняя/ощущаемая), влажность, точка росы, осадки, снег, облачность, ветер (скорость, порывы,
направление), солнечное сияние, UV. Плюс прогноз на 7 дней и текущая погода.

**Визуализация (вместо «+20/−10»):**
1. **Кольцевой график года** — 12 секторов, цвет = средняя температура, толщина = осадки. Один взгляд — весь год.
2. **Четыре сезона** — карточки: средняя и ощущаемая температура, дней с осадками, часов солнца, влажность,
   ветер; фон карточки — градиент сезона.
3. **Индекс комфорта для студента** (наш) — сколько дней в году «приятно» (+10…+25 °C, без сильного ветра и дождя),
   сколько «морозно» (< −15), «жарко» (> 30). Показывать как полосу-стек.
4. **Роза ветров** — направление и сила по месяцам.
5. **Живой слой ветра и облаков на карте** — embed Windy (бесплатный iframe без ключа) или тайлы OpenWeatherMap
   (температура/облака/ветер, бесплатный ключ). Показываем во вкладке «Климат» под кампусом.
6. **«Как ощущается»** — 3–4 предложения от LLM строго по числам (шаблон без ключа): «Зима сухая и морозная,
   с декабря по февраль средняя −8 °C, солнечных дней много; лето жаркое до +30 °C, дождей мало».

Все числа — со ссылкой на Open-Meteo и годом расчёта.

## 6. Транспорт, стоимость жизни, «что есть в городе»

- **Транспорт:** остановки в радиусе 800 м (Overpass, есть), маршрут и время до центра города пешком/на машине
  (OSRM demo-сервер, бесплатно, с User-Agent; fallback — прямая линия), станции метро/ЛРТ рядом.
- **Что рядом (иконки):** Overpass в радиусе 1 км — кафе, супермаркеты, парки, спортзалы, аптеки, банки, ТЦ,
  кинотеатры; счётчики + пины на карте. Плюс «время до аэропорта/вокзала» через OSRM.
- **Стоимость жизни:** Numbeo API платный ($260/мес) — нет. Делаем **свой курируемый датасет** для городов
  Казахстана и ЦА (аренда 1-комн., проездной, обед в столовой, продукты/мес) с указанием источника и месяца
  (Krisha.kz, stat.gov.kz, WhereNext — открытые данные ICP/OECD для мировых городов). Для городов без данных —
  честно «нет данных». Показываем как «ориентировочный бюджет студента в месяц» с разбивкой.

## 7. ИИ-агенты и достоверность (главный критерий)

Наш пайплайн уже устроен как цепочка агентов, называем это в презентации так:

| Агент | Что делает | Реализация |
|---|---|---|
| **Scout** (поиск) | Собирает кандидатов из источников, где принадлежность гарантирована: сайт вуза, категория и «depicts» Commons, статьи Википедии, геофото в полигоне кампуса, Mapillary/Flickr/Places | `pipeline/sources/*`, параллельно, таймауты |
| **Inspector** (проверка) | Каждому фото — независимые сигналы: источник, геометка внутри полигона OSM, семантика CLIP, название в подписи, повтор в источниках, дата → уверенность 0–1 | `verify.py` |
| **Curator** (дубли и мусор) | SHA-1/pHash — копии, косинус CLIP — похожие, zero-shot — логотипы/карты/документы/портреты | `dedup.py`, `vision.py` |
| **Judge** (второе мнение) | Для фото с уверенностью 0.30–0.65 vision-LLM отвечает по строгой схеме: «это фотография университетского кампуса/общежития/…? да/нет + категория» и корректирует балл | Gemini 2.5 Flash free tier (10 RPM, 1 500 запросов/день, без карты) или Claude при ключе |
| **Writer** (описание) | Описание по фото с уверенностью > 0.5 (подписи, категории, здания OSM) + Wikipedia/Wikidata, каждое предложение с источником | `describe.py`, тот же промпт для Claude/Gemini, шаблон без ключа |

Пороги: < 0.30 — удаляем из выдачи (видно только в «Отклонено»), 0.30–0.65 — «вероятно», ≥ 0.65 — «подтверждено».
Панель «Почему мы уверены» на каждом фото — то, что жюри увидит, кликнув.

## 8. Дизайн-система

- **Цвета:** белый `#FFFFFF`, синий `#1D4ED8` (акцент) + `#0B1F4B` (глубокий) , чёрный `#0A0A0A` (текст/космос).
  Статусы: зелёный подтверждено, янтарный вероятно, красный отклонено. Брошюра — фиолетовый, реальность — бирюзовый.
- **Фон:** топографический узор — SVG изолинии из шума (d3-contour + simplex-noise, генерируется один раз в скрипт,
  сохраняется как статичный SVG ~30 КБ), opacity 4–6%, на лендинге медленно «дышит».
- **Типографика:** Inter (или Manrope) для интерфейса, моноширинный для цифр и id.
- **Движение:** перелёт 2.5 с, возведение зданий 1.2 с, карточки появляются каскадом по мере стрима (уже есть).
- **Диаграммы:** кольцо года, сезоны, стек комфорта, роза ветров, покрытие по категориям (есть), таймлайн (есть),
  «брошюра vs реальность» (есть). Библиотека: Recharts или D3 — Recharts быстрее для команды.
- **Тема «космос → кампус»:** лендинг тёмный (космос), профиль светлый (минимализм). Переход — перелёт.

## 9. Сохранение, сравнение, ИИ-чат

- **Сохранение карточек:** уже есть (localStorage: избранное, сохранённые профили, план визита). Добавить экран
  «Мои вузы» с карточками и кнопкой «сравнить выбранные».
- **Сравнение:** слева/справа карточки (факты, покрытие, климат, транспорт, бюджет, 4 фото по категориям),
  посередине — блок ИИ: «Плюсы и минусы по данным профилей» (списком, с пометками источников) + кнопка «Задать вопрос».
- **Чат:** контекст = JSON двух профилей + анкета пользователя (что важно: бюджет, климат, общежитие, город).
  Системное правило: отвечать только по данным профилей, при отсутствии данных так и говорить, не давать гарантий.
  Модель: Gemini 2.5 Flash (бесплатно) или Claude. Стриминг ответа.

Часы: «Мои вузы» 2, сравнение 3, чат 4.

## 10. Дополнительные идеи от меня (что ещё выделит на защите)

1. **«Кампус возводится»** — анимация 3D-зданий после перелёта (см. §2). Дёшево, эффектно.
2. **Солнце и сезон на 3D-карте** — ползунок «месяц/час»: MapLibre `light` меняет направление света, тени зданий
   и цвет неба; зимой — снежная палитра карты. Связывает климат и 3D.
3. **3D-фото с параллаксом** (см. §3.2) — честный «объём» реальных фото.
4. **«Брошюра vs реальность»** — есть; на защите это самый цитируемый экран.
5. **Паспорт фото с сигналами** — есть; главный ответ на критерий точности.
6. **Режим жюри** — есть; показывает автоматичность и тайминги.
7. **Таймлайн «как менялся кампус»** — есть; добавить ползунок годов на 3D-карте (здания с `start_date` из OSM).
8. **Индекс покрытия и честные пустые состояния** — есть.
9. **«15 минут пешком»** — изохрона от кампуса (Valhalla/OSRM) и что в неё попадает. P2.
10. **OG-карточки для шаринга** — ссылка на профиль превращается в красивую карточку в Telegram (серверный рендер PNG). P2.
11. **Голосовой ввод названия** (Web Speech API) — 30 минут, приятная мелочь для мобильной версии. P2.
12. **Сравнение «климат-двойников»**: «климат Астаны похож на Монреаль» — по расстоянию между профилями Open-Meteo. P2.

### 11.2. Как связано (поток данных)

```
Пользователь ─ вводит название ─▶ /api/search (индекс + Wikidata) ─▶ QID
   │
   ├─▶ Frontend: глобус flyTo к координатам (из индекса, мгновенно)
   │       └─ параллельно: OpenFreeMap 3D-здания, Overpass POI, OSRM маршрут, Windy — клиентские запросы
   │
   └─▶ /api/profile/{qid}/stream (SSE)
          facts (1 c) → campus (Overpass, параллельно) → источники (параллельно, 6 с таймаут)
          → загрузка → CLIP/хэши → уверенность → предварительные фото (event photos, с 3–4 с)
          → финальная сборка: дубли, категории, покрытие, описание, климат → profile (≤ 25 с) → SQLite
```

Если профиль уже в кэше — событие `profile` приходит сразу, перелёт всё равно играет (2.5 с), фото появляются
к его концу. Так демо всегда «в 30 секунд», а прогретые вузы — за 3.

### 11.3. Контракт между частями

- Python отдаёт JSON по схеме `GET /api/schema`; Next.js-часть генерирует Zod-типы из неё.
- Node-коллекторы могут добавлять кандидатов через `POST /api/ingest` — проверка всё равно на Python-стороне.
- Общие хэши (sha1/dhash/phash) и ключи localStorage описаны в `INTEGRATION.md`.
