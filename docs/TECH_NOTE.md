# Техническая справка CampusLense

## Модели и AI-компоненты

| Компонент | Модель / метод | Где исполняется | Назначение |
|---|---|---|---|
| Семантика и категории | CLIP ViT-B/32 (open_clip, веса laion2b_s34b_b79k) | сервер, CPU | zero-shot по 8 категориям и 8 классам мусора; эмбеддинги для поиска похожих |
| Дубли | SHA-1, pHash 8×8 (Hamming ≤ 8), dHash, косинус эмбеддингов ≥ 0.93 | сервер | копии и визуально похожие снимки |
| ИИ-инспектор | Gemini `gemini-3.5-flash-lite` на Vertex AI (location `global`, media_resolution LOW — 280 токенов на фото); страхующая копия запроса через 4,5 с; резерв — AI Studio (`3.1-flash-lite`) | API | **каждое** фото рядом с эталоном вуза: место (вуз / город / другое / не фото), уверенность 0–3, категория, наглядность, красота кадра, флаги, эпоха; очередь с приоритетом, пачки по 8–12, кэш по (вуз, SHA-1) |
| Редактор обложки | Gemini, один сравнительный запрос на ~25 кандидатов (640 px) | API | 5 кадров шапки профиля: кампус снаружи первым, затем разные стороны жизни |
| Куратор | ранжирование уверенность × наглядность + разнообразие (косинус CLIP < 0.86) | сервер | 6–8 лучших кадров на категорию |
| Описание и справки | Gemini, JSON-схема с номерами источников | API | описание вуза, «Что есть на кампусе», сводка сайта вуза по темам, рассказ о климате |
| ИИ-советник сравнения | Gemini на Vertex AI, потоковый ответ | API | ответы только по фактам двух профилей, сайтов вузов, климата и бюджета; выбор оставляет пользователю |
| Кадры из видео | ffmpeg + CLIP (промпты «место» против «влог») | сервер | из роликов TikTok, Reels и YouTube берутся кадры с местом, а не обложка |
| Карты глубины | Depth Anything V2 Small (transformers, CPU) | сервер | параллакс «3D-фото»; пиксели не меняются |
| Поиск названия | rapidfuzz WRatio по 40 000 вариантов имён (ru/kk/en, транслитерация, города) + Wikidata API | сервер | устойчивость к опечаткам |

## Проверка результата

- Каждое фото несёт список сигналов с весами и итоговую уверенность (формула в `docs/ARCHITECTURE.md` §3).
- Кликабельный источник у каждого фото; отклонённые остаются видимыми с причиной.
- Вкладка «Проверка»: этапы с временем, статусы источников с числом кандидатов, отклонённые с причинами, запросы, журнал, JSON профиля, `GET /api/schema`.
- Точность на 223 размеченных фото: precision 0,94, recall 0,94, категория 0,95, подборка 0,93.
- `scripts/eval.py` считает precision / recall / F1 верификации по ручной разметке `data/labels.json`.
- `scripts/smoke.py` прогоняет пайплайн без браузера; `scripts/rebuild.py --labelled` пересобирает размеченные вузы.
- Правила для поисковой выдачи строже, чем для каналов вуза: фото из поиска без вердикта ИИ не показывается, а если
  на странице нет названия вуза, нужна полная уверенность ИИ (3/3).
- Время: первый профиль за ~22–24 с — источники отдают найденное к сроку; затем второй проход без лимита времени, профиль обновляется сам.

## Безопасность и ограничения

- Секреты только в `.env`; в репозитории нет ключей. Google-ключ фронтенда ограничен по referrer.
- Никаких сгенерированных изображений в роли фото кампуса; катсцены (если будут) подписаны как анимация.
- SSL-fallback без проверки сертификата используется только для GET публичных страниц/картинок сайтов вузов с неполной цепочкой.
- Публичные API имеют лимиты: таймауты и деградация по источникам, кэш профилей/климата/контекста в SQLite.
- Персональные данные не собираются; localStorage хранит только предпочтения пользователя на его устройстве.
